# Справочник по Инею

## Установка и запуск

Нужен Python 3.10 или новее. В папке проекта создайте виртуальное окружение.

```sh
python -m venv .venv
```

Активируйте его командой `source .venv/bin/activate` на Linux или `.venv\Scripts\Activate.ps1` в Windows PowerShell.

```sh
python -m pip install -r requirements.txt
python server.py
```

На сервере откройте `http://localhost:8000`. Для входа с другого компьютера укажите IP сервера и тот же порт. Адрес и порт прослушивания задаются параметрами `MONITORING_SIP_HOST` и `MONITORING_SIP_PORT` в `.env`.

При первом запуске пароль пользователя `admin` появится в `users_data/first-start.txt` в папке данных. После успешного входа файл удаляется. Администратор создаёт учётные записи на вкладке «Пользователи». Токен событий доступен в настройках Action URL.

### Установка без интернета

Выберите [Windows-установщик или Linux ZIP](../README.md#скачать-иней-15-preview) для своей платформы. В комплект входят Python и зависимости. [Инструкция по установке](../offline/ИНСТРУКЦИЯ.txt).

### Резервная копия и восстановление

Остановите сервер и скопируйте `auth.json`, `.env` и папку `users_data/`. При установке через мастер Windows их можно найти в выбранной папке рабочих данных. При запуске из распакованного ZIP папка по умолчанию — `app/`. Мастер Windows умеет переносить данные из старой установки.

Если пароль `admin` утерян, остановите сервер и переименуйте `auth.json`. При следующем запуске появится новый `admin` с новым паролем и токеном. Потребуется заново создать остальные учётные записи и заменить токены в настройках телефонов.

Журнал приложения находится в `users_data/app.log` в папке данных. Для отправки сведений об ошибке сформируйте диагностический отчёт.

## Карточки

Перетащите карточку на другую в той же группе. На сенсорном экране тяните за ручку внизу карточки. Потяните за правый нижний угол, чтобы изменить размер. Размер и порядок сохраняются на сервере.

С клавиатуры выберите ручку клавишей Tab и используйте стрелки. Клавиша Home на ручке размера возвращает исходный размер.

## Подключение узла

В админке откройте «Подключение узла» и импортируйте файл, выданный администратором подключения. Телефоны отправляют Action URL на адрес своего узла. При временном обрыве узел продолжает принимать события и показывать местную историю.

Если адрес подключения изменился, укажите его в форме «Сменить адрес». При смене доверенного сертификата получите обновлённые настройки у администратора.

Начиная с Инея 1.4 подключённые узлы участвуют в проверке доступности сети. Администратор задаёт список целей на сервере мониторинга. Узел получает список при синхронизации, проверяет адреса по ICMP и передаёт свежие результаты. На Linux для проверки нужна команда `ping` из iputils, на Windows используется системный ICMP.

### Обновление узла

Когда доступна новая сборка, администратор узла увидит кнопку «Обновить». Нажмите её, чтобы скачать пакет через внутреннюю сеть и перезапустить службу. Карточки, настройки и история сохраняются. Кнопка остаётся на панели до успешной установки.

## Виртуальные телефоны

На компьютере, где установлен комплект, запустите `start_windows.bat --lab --open` или `bash start_linux.sh --lab --open`. Из исходников используйте `python -m simulator --open`. На этом компьютере стенд доступен по адресу `http://127.0.0.1:18080/lab` и из вкладки «Тесты».

Стенд содержит три виртуальных телефона и отдельную панель мониторинга. Звонки, удержание, DND и перевод можно проверить в симуляции. Сценарии отправляют Action URL в тестовую историю на этом компьютере. [Подробнее о стенде](../simulator/README.md).

## Настройка телефонов Yealink

1. Добавьте карточку с номером телефона.
2. Откройте «Диагностика → Настройка телефонов». Укажите адрес сервера и владельца карточки. Для аппарата с одним SIP-номером выберите карточку, для общей DECT-базы или нескольких учётных записей выберите «Авто». Если один IP указан у нескольких карточек владельца, фиксированный номер недоступен.
3. Нажмите «Скачать CFG для Yealink». В веб-интерфейсе аппарата откройте «Настройки → Конфигурация → Импорт CFG». Для ручного ввода скопируйте нужные адреса в «Функции → Action URL».

CFG содержит поля Action URL для Yealink T53. Состав полей зависит от модели и прошивки, в том числе у DECT-баз.

### Проверка телефона

Кнопка «Проверить телефон» сравнивает поля Action URL перед импортом CFG. Поддержка проверена на Yealink SIP-T30 с прошивкой `124.87.14.1`. Укажите IP одной карточки выбранного пользователя.

На сервере задайте сети телефонов через запятую в `YEALINK_ALLOWED_CIDRS`, логин в `YEALINK_ADMIN_USER` и пароль в `YEALINK_ADMIN_PASSWORD`. Для проверки HTTPS нужна доверенная цепочка с IP в сертификате либо подтверждённый отпечаток сертификата в `YEALINK_CERT_SHA256`.

В «Диагностика → Последние события от телефонов» можно сверить исходные поля события и версию прошивки. Если журнал показывает неоднозначность номера, проверьте IP карточек с этим номером. В режиме «Авто» сервер берёт номер из `$active_user`, когда телефон заполняет это поле. При пустом номере сервер ищет карточку по ранее полученному MAC или по IP. Привязки MAC сбрасываются при перезапуске. Для общей базы с одним IP и MAC нужен номер от телефона.

### Справочник событий

Телефон отправляет событие на `/event` методом GET. Токен берётся из учётной записи владельца карточки.

```text
http://<ip-сервера>:8000/event?token=<event_token>&state=<STATE>&local=<номер-карточки>&remote=$remote&called_number=$calledNumber&ip=$ip&mac=$mac&call_id=$call_id&model=$model&firmware=$firmware
```

При исходящем вызове `$calledNumber` может подставляться вместо пустого `$remote`. Для входящего используется номер собеседника из события.

Поля 28 и 29 отвечают за переходы между состояниями «В покое» и «Занят». Чтобы сверить их порядок, снимите трубку и найдите `idle_to_busy` в журнале событий.

Если при ответе по громкой связи или через гарнитуру телефон пропускает `call_established`, настройте события громкой связи и гарнитуры из полей 38 и 39.

При двух одновременных звонках история объединяет их в одну запись от начала первого до конца последнего. Событие `busy_to_idle` помогает завершить звонок, когда телефон освободится.

Прежние значения `Setup`, `Ringing`, `Connected`, `Idle`, `Hold`, `DND`, `OffHook` и `OnHook` по-прежнему принимаются. Прежний `DND` сбрасывается при завершении звонка. Состояние `dnd_on` держится до `dnd_off`.
