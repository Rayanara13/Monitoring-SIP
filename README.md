# Monitoring SIP

Веб-панель мониторинга SIP-телефонов Yealink в реальном времени: состояние трубок (в покое / входящий / разговор / удержание / DND / офлайн), история звонков, мультипользовательский доступ. Flask + Flask-SocketIO, обновления в браузере мгновенные — через WebSocket.

**Версия:** Rel 1.2

**Виртуальный стенд:** три интерактивных телефона и настоящая панель мониторинга — `python -m simulator --open` или `start_phone_lab.cmd` на Windows. Подробности и сценарий первого звонка: [simulator/README.md](simulator/README.md).

## Возможности

- Карточки телефонов с живым статусом и таймером разговора
- Ping-мониторинг доступности трубок (debounce: OFFLINE после 2 неудач подряд)
- История звонков в SQLite с фильтрацией по номеру / дате
- Мультипользовательский режим: у каждого пользователя свой набор карточек + общие (shared) наборы
- Защита: rate-limit на логин и `/event`, блокировка по IP, токен на события
- Структурированный JSONL-лог (`users_data/app.log`) для диагностики, ротация, хранение 24ч
- Оверлей «сервер обновился» при рестарте — клиент предлагает обновить страницу

## Требования

- Python 3.10+
- Linux или Windows (ping кросс-платформенный)

## Установка и запуск

```bash
git clone https://github.com/Rayanara13/Monitoring-SIP.git
cd Monitoring-SIP

python -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -r requirements.txt

python server.py
```

Сервер слушает `0.0.0.0:8000`. Панель: `http://<ip-сервера>:8000/`.

### Первый запуск

При первом старте автоматически создаются:

- **`auth.json`** — пользователь `admin` со случайным паролем. Логин, пароль и `event_token` печатаются в консоль **один раз** — сохраните их (в файле остаётся только хэш пароля).
- **`.env`** — секретный ключ сессий (`APP_SECRET_KEY`), персистентный между рестартами.
  Сюда же при необходимости — `TARGET_IP=<адрес>` (и `TARGET_PORT`, по умолчанию 8000): центральный сервер, на который дублируются все GET-запросы, включая события `/event`. Не задан — дублирования нет (адреса по умолчанию с Rel 1.1 нет).
- **`users_data/`** — данные пользователей, БД истории (`call_history.db`), лог (`app.log`).

Все три пути в `.gitignore` — в репозиторий не попадают.

Новых пользователей регистрирует admin через панель (`/register`), у каждого свой `event_token`.

## Настройка телефонов Yealink

В веб-интерфейсе трубки/базы: **Функции → Action URL** (Features → Action URL). События шлются GET-запросом на `/event`:

```
http://<ip-сервера>:8000/event?token=<event_token>&state=<STATE>&local=<номер-карточки>&remote=$remote&called_number=$calledNumber&ip=$ip&mac=$mac&call_id=$call_id&model=$model&firmware=$firmware
```

В панели открой **Тесты → Настройка телефонов**, выбери владельца карточек и адрес сервера. Для **отдельного устройства с одним SIP-номером** выбери конкретную карточку телефона. Номер подставится явно в `local` во всех 48 строках сразу. Пробный круг звонков для обучения номера не нужен. При смене пользователя карточку нужно выбрать заново. Для общей DECT-базы или аппарата с несколькими SIP-аккаунтами используй «Авто»: фиксированный номер в общей конфигурации ошибочно приписал бы ему все звонки. Если несколько карточек выбранного пользователя имеют один непустой IP, фиксированный режим блокируется. Неизвестные/пустые IP или наборы разных пользователей не позволяют автоматически обнаружить все общие базы.

Для совместимых **Yealink** нажми **«Скачать CFG»** и импортируй файл в веб-интерфейсе телефона: **Settings → Configuration → Import CFG Configuration File**. Это один файл с настройками Action URL; он не содержит настроек SIP-регистрации. Для ручной настройки остаются «Копировать» у каждой строки и «Скопировать все». Поддержка отдельных полей зависит от модели и прошивки: полный набор из 48 соответствует таблице T53, а у DECT/W70B документирован другой состав. Совместимость импорта этого CFG с ТЕЛТА «Спектр-101» пока не подтверждена.

Администратор может сверить поля Action URL перед импортом через **«Проверить телефон»**. Подтверждённый профиль проверки — **SIP-T30 `124.87.14.1`**. Укажи IP, совпадающий с адресом одной карточки выбранного пользователя. Сервер подключается к веб-интерфейсу телефона по HTTPS и показывает число совпадающих, пустых и отличающихся полей. Применение CFG выполняется в веб-интерфейсе аппарата.

Для проверки серверу нужен доступ к сети аппаратов. В `.env` сервера или окружении процесса задаются `YEALINK_ALLOWED_CIDRS` (явные диапазоны сети телефонов через запятую), `YEALINK_ADMIN_USER` и `YEALINK_ADMIN_PASSWORD`. Для самоподписанного сертификата одного тестового аппарата можно задать `YEALINK_CERT_SHA256` с его проверенным отпечатком. Без отпечатка нужна доверенная цепочка и IP в сертификате. Учетные данные Yealink используются на сервере. Для устройства с заполненными полями сверяй различия перед импортом: поля другой интеграции могут быть заняты.

При отсутствии номера собеседника смотри **журнал последних событий**: он сохраняет исходные `local`, `remote`, `called_number`, модель и прошивку, без токена. Пустое значение и неподставленный текст `$remote` различаются. Если номер впервые пришёл при ответе снятием трубки, громкой связью или гарнитурой, он сохраняется в карточке и истории; отдельное событие Established для этого не нужно. `$calledNumber` используется как резерв собеседника только в событии исходящего вызова; для входящего он не применяется, чтобы не показать собственный номер. Если прошивка не подставляет ни один макрос, сервер не может восстановить отсутствующий номер из URL.

Режим **«Авто ($active_user)»** оставлен для совместимых телефонов. По админ-гайду `$active_user` заполнен только в звонке, поэтому для DND, переадресаций и регистрации сервер ищет номер по ранее выученному `$mac`, затем по IP карточки — в наборе владельца токена. MAC-привязки живут только до перезапуска. Общая DECT-база может обслуживать несколько номеров с одним IP/MAC: для неё необходим реальный номер аккаунта из макроса телефона, а фиксированный номер в общей конфигурации не подходит. Обучение только одной трубки не доказывает однозначность базы; при совпадении IP нескольких карточек сервер не применяет такую MAC-привязку. Пустые события общей базы остаются неопределёнными. IP отправителя и `X-Forwarded-For` для поиска не используются. Непустой `$call_id` помогает сопоставлять поздние и повторные события с известным вызовом.

Событие обновляет карточку из набора владельца токена. Копии одной карточки с тем же номером и IP обновляются вместе. Если один номер связан с разными или неполными адресами в нескольких наборах, журнал показывает неоднозначность и мониторинг ждёт исправления карточек.

Формат CFG, имена параметров и макросы сверены с документацией производителя: [Yealink T53 — Remote Control](https://support.yealink.com/docs/sip-t53/remote-control/93527fc627104ded93cf7f11a1c2dbe2), [импорт CFG](https://support.yealink.com/docs/w70b/analyze-configuration-files/7b50a30c54894147b21c4d63cdd63d48), [формат CFG](https://support.yealink.com/docs/w73p-w70b-w73h/manage-configuration-files/6fefcadeef444680b2cedd9315aca4e7). Переносить значения макросов и ключи CFG на ТЕЛТА без проверки его прошивки нельзя.

Перевод в прошивке местами мимо: «Отклонено» — это Terminated, «Ошибка» — Missed Call, «режим ожидания» — Call Waiting. Соответствие взято по порядку полей из админ-гайда Yealink (T2/T19/T4). Для полей 43–48 гайд имён не даёт — `state` для них придуман нами.

⚠️ **Проверить пару 28/29.** Если поменять их местами, карточка будет застревать в «Занят». Проверка: сними трубку — в журнале на вкладке «Тесты» должно прийти «Занятость абонента / idle_to_busy».

**Ответ без снятия трубки.** На части телефонов при ответе кнопкой громкой связи «Связь установлена» не приходит — карточка висела во «Входящем», и через 60 с её сбрасывал watchdog. Теперь ответом считается любое из: «Связь установлена», «Ответил на вызов», «Громкая связь», «Гарнитура», «Трубка снята» — пока карточка во «Входящем». Для этого у таких телефонов должны быть заполнены поля 38–39.

**Две линии** (второй звонок поверх разговора). Action URL не говорит, к какой линии относится событие, поэтому сервер считает линии (значок «📞 Линий: 2»). Второй входящий карточку не трогает, звонок со второй линией пишется в историю одной записью — от начала первого до конца последнего. «Одна линия кончилась, телефон ещё занят» сервер допускает, только если телефон шлёт «Занято» (Busy To Idle): оно поправит карточку, когда телефон реально освободится. Без него Terminated / On Hook, как раньше, завершают всё.

Старые значения `Setup`, `Ringing`, `Connected`, `Idle`, `Hold`, `DND`, `OffHook`, `OnHook` по-прежнему принимаются — уже настроенные телефоны перенастраивать не обязательно. Старый `state=DND` гаснет с концом звонка, как раньше; новый «Включение DND» (`dnd_on`) держится до «Отключение DND».

Номер телефона появится в панели после того, как admin (или владелец набора) добавит карточку с этим номером — события от незарегистрированных номеров игнорируются.

## Офлайн-комплект (Windows + Linux, без интернета)

Для машины без интернета: один zip со встроенным Python 3.13 (Windows x64 и Linux x86_64)
и всеми зависимостями в `vendor/` — распаковал и запустил, без pip/venv. Если встроенный
Python не стартует, подхватится системный 3.10+. Собирается на машине с интернетом:

```bash
bash offline/build_kit.sh    # -> dist/MonitoringSIP_offline_<hash>.zip
```

В архив идёт код из HEAD (незакоммиченное не попадает). Инструкция для установщиков —
`offline/ИНСТРУКЦИЯ.txt` (кладётся в корень архива). Версии зависимостей — `offline/requirements.lock`.

## Сборка в exe (опционально)

Для деплоя на Windows без Python есть спека PyInstaller:

```bash
pip install pyinstaller
pyinstaller server.spec
```

Готовый бинарь — в `dist/`. HTML-шаблоны (`login.html`, `panel.html`) и `static/` вшиты в сборку.
