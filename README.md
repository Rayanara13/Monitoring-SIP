# Monitoring SIP

Веб-панель мониторинга SIP-телефонов Yealink в реальном времени: состояние трубок (в покое / входящий / разговор / удержание / DND / офлайн), история звонков, мультипользовательский доступ. Flask + Flask-SocketIO, обновления в браузере мгновенные — через WebSocket.

**Версия:** Rel 1.1

## Возможности

- Карточки телефонов с живым статусом и таймером разговора
- Ping-мониторинг доступности трубок (debounce: OFFLINE после 2 неудач подряд)
- История звонков в SQLite с фильтрацией по номеру / дате
- Мультипользовательский режим: у каждого пользователя свой набор карточек + общие (shared) наборы
- Защита: rate-limit на логин и `/event`, блокировка по IP, токен на события
- Структурированный JSONL-лог (`users_data/app.log`) для диагностики, ротация, хранение 24ч
- Оверлей «сервер обновился» при рестарте — клиент предлагает обновить страницу

## Требования

- Python 3.10+
- Linux или Windows (ping кросс-платформенный)

## Установка и запуск

```bash
git clone https://github.com/Rayanara13/Monitoring-SIP.git
cd Monitoring-SIP

python -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -r requirements.txt

python server.py
```

Сервер слушает `0.0.0.0:8000`. Панель: `http://<ip-сервера>:8000/`.

### Первый запуск

При первом старте автоматически создаются:

- **`auth.json`** — пользователь `admin` со случайным паролем. Логин, пароль и `event_token` печатаются в консоль **один раз** — сохраните их (в файле остаётся только хэш пароля).
- **`.env`** — секретный ключ сессий (`APP_SECRET_KEY`), персистентный между рестартами.
  Сюда же при необходимости — `TARGET_IP=<адрес>` (и `TARGET_PORT`, по умолчанию 8000): центральный сервер, на который дублируются все GET-запросы, включая события `/event`. Не задан — дублирования нет (адреса по умолчанию с Rel 1.1 нет).
- **`users_data/`** — данные пользователей, БД истории (`call_history.db`), лог (`app.log`).

Все три пути в `.gitignore` — в репозиторий не попадают.

Новых пользователей регистрирует admin через панель (`/register`), у каждого свой `event_token`.

## Настройка телефонов Yealink

В веб-интерфейсе трубки/базы: **Функции → Action URL** (Features → Action URL). События шлются GET-запросом на `/event`:

```
http://<ip-сервера>:8000/event?token=<event_token>&state=<STATE>&local=$active_user&remote=$remote&ip=$ip&mac=$mac&call_id=$call_id
```

Готовые строки под каждое поле, с токеном и адресом сервера, — в панели: **Тесты → Настройка телефонов** (кнопка «Копировать» у каждой строки и «Скопировать все»). Там же **журнал последних событий** — по нему видно, что телефон реально шлёт и к какому номеру событие привязалось.

`$active_user`, `$remote`, `$ip`, `$mac`, `$call_id` — переменные Yealink, телефон подставляет их сам. По админ-гайду `$active_user` заполнен только в звонке, поэтому для DND, переадресаций, регистрации и смены IP номер ищется по `$mac` (сервер запоминает MAC из прошлых событий с номером), затем по IP карточки — **только в наборе владельца токена и только если адрес однозначен**. У DECT-базы один IP и MAC на несколько трубок: такие события без `$active_user` не привязываются (видно в журнале как «номер не определён»). IP отправителя и `X-Forwarded-For` для поиска не используются. `$call_id` пока только пишется в журнал и лог.

| № | Поле (русская прошивка) | Событие Yealink | state | Что в панели |
|---|---|---|---|---|
| 1 | Настройка завершена | Setup Completed | `setup_completed` | телефон перезагрузился — сброс зависшего звонка |
| 2 | Зарегистрирован | Registered | `registered` | выход из «Нет регистрации» |
| 3 | Не зарегистрировано | Unregistered | `unregistered` | «Нет регистрации» (группа Offline) |
| 4 | Ошибка регистрации | Register Failed | `register_failed` | «Нет регистрации» |
| 5 | Трубка снята | Off Hook | `off_hook` | «Снята трубка»; пока звонит — ответ; во время разговора игнорируется |
| 6 | Трубка положена | On Hook | `on_hook` | конец звонка, запись в историю (при двух линиях игнорируется) |
| 7 | Входящий вызов | Incoming Call | `incoming_call` | «Входящий вызов»; поверх разговора — карточку не трогает |
| 8 | Исходящий вызов | Outgoing Call | `outgoing_call` | «Исходящий вызов» |
| 9 | Связь установлена | Established | `call_established` | «Разговор» |
| 10 | Отклонено | Terminated | `call_terminated` | конец звонка, запись в историю (при двух линиях — конец одной, см. ниже) |
| 11 | Включение DND | Open DND | `dnd_on` | «DND» (во время звонка — значок) |
| 12 | Отключение DND | Close DND | `dnd_off` | выход из DND |
| 13–18 | Вкл./выкл. переадресация «Всегда», «Занято», «Нет ответа» | Open/Close Always, Busy, NoAnswer Forward | `always_fwd_on/off`, `busy_fwd_on/off`, `no_answer_fwd_on/off` | значок «↪ всегда, занято…» |
| 19–21 | Перевод звонка, Слепой трансфер, Сопроводительный трансфер | Transfer Call, Blind / Attended Transfer | `transfer_call`, `blind_transfer_call`, `attended_transfer_call` | «Перевод вызова» |
| 22 | Удержание | Hold | `hold` | «Удержание» |
| 23 | Возврат | UnHold | `unhold` | «Разговор» |
| 24 | Тишина | Mute | `mute` | значок «Микрофон выкл» |
| 25 | Вкл.микро | UnMute | `unmute` | значок снят |
| 26 | Ошибка | Missed Call | `missed_call` | счётчик «Пропущено: N» |
| 27 | Смена IP-адреса | IP Changed | `ip_change` | новый IP — в карточку (иначе пинг уводит в Offline) |
| 28 | Занятость абонента | Idle To Busy | `idle_to_busy` | «Занят», если других подробностей нет |
| 29 | Занято | Busy To Idle | `busy_to_idle` | телефон свободен — конец всех линий |
| 30 | Отбой входящего вызова | Reject Incoming Call | `reject_incoming_call` | отбой входящего |
| 31 | Ответил на вызов | Answer New-In Call | `answer_new_incoming_call` | «Разговор» с новым собеседником |
| 32 | Ошибка трансфера | Transfer Failed | `transfer_failed` | обратно в «Разговор» |
| 33 | Завершение перевода | Transfer Finished | `transfer_finished` | звонок передан — покой |
| 34 | Переадресация входящих вызовов | Forward Incoming Call | `forward_incoming_call` | счётчик «Переадресовано: N» |
| 35 | Завершение настройки | Autop Finish | `setup_autop_finish` | только «последнее событие» |
| 36–37 | Вкл./откл. режима ожидания | Open/Close Call Waiting | `call_waiting_on/off` | значок «Ожидание вызова выкл» |
| 38 | Гарнитура | Headset | `headset` | значок 🎧 до конца звонка; пока звонит — ответ |
| 39 | Громкая связь | Handfree | `handfree` | значок 🔊 до конца звонка; пока звонит — ответ |
| 40 | Отмена вызова | Cancel Call Out | `cancel_callout` | отмена исходящего |
| 41 | Вызываемый абонент занят | Remote Busy | `remote_busy` | «Абонент занят» до отбоя трубки |
| 42 | Вызов отклонен | Call Remote Canceled | `call_remote_canceled` | звонящий бросил трубку |
| 43 | View Missed Call | View Missed Call | `view_missed_call` | счётчик пропущенных обнулён |
| 44 | View Forwarded Call | View Forwarded Call | `view_forwarded_call` | счётчик переадресованных обнулён |
| 45 | Периферийная информация | Peripheral Information | `peripheral_information` | только «последнее событие» |
| 46 | VPN IP | VPN IP | `vpn_ip` | значок VPN (адрес в подсказке) |
| 47 | SIP INFO Display Update | SIP INFO Display Update | `sip_info_display_update` | только «последнее событие» |
| 48 | Конференция с | Conference | `conference` | «Конференция» |

Перевод в прошивке местами мимо: «Отклонено» — это Terminated, «Ошибка» — Missed Call, «режим ожидания» — Call Waiting. Соответствие взято по порядку полей из админ-гайда Yealink (T2/T19/T4). Для полей 43–48 гайд имён не даёт — `state` для них придуман нами.

⚠️ **Проверить пару 28/29.** Если поменять их местами, карточка будет застревать в «Занят». Проверка: сними трубку — в журнале на вкладке «Тесты» должно прийти «Занятость абонента / idle_to_busy».

**Ответ без снятия трубки.** На части телефонов при ответе кнопкой громкой связи «Связь установлена» не приходит — карточка висела во «Входящем», и через 60 с её сбрасывал watchdog. Теперь ответом считается любое из: «Связь установлена», «Ответил на вызов», «Громкая связь», «Гарнитура», «Трубка снята» — пока карточка во «Входящем». Для этого у таких телефонов должны быть заполнены поля 38–39.

**Две линии** (второй звонок поверх разговора). Action URL не говорит, к какой линии относится событие, поэтому сервер считает линии (значок «📞 Линий: 2»). Второй входящий карточку не трогает, звонок со второй линией пишется в историю одной записью — от начала первого до конца последнего. «Одна линия кончилась, телефон ещё занят» сервер допускает, только если телефон шлёт «Занято» (Busy To Idle): оно поправит карточку, когда телефон реально освободится. Без него Terminated / On Hook, как раньше, завершают всё.

Старые значения `Setup`, `Ringing`, `Connected`, `Idle`, `Hold`, `DND`, `OffHook`, `OnHook` по-прежнему принимаются — уже настроенные телефоны перенастраивать не обязательно. Старый `state=DND` гаснет с концом звонка, как раньше; новый «Включение DND» (`dnd_on`) держится до «Отключение DND».

Номер телефона появится в панели после того, как admin (или владелец набора) добавит карточку с этим номером — события от незарегистрированных номеров игнорируются.

## Офлайн-комплект (Windows + Linux, без интернета)

Для машины без интернета: один zip со встроенным Python 3.13 (Windows x64 и Linux x86_64)
и всеми зависимостями в `vendor/` — распаковал и запустил, без pip/venv. Если встроенный
Python не стартует, подхватится системный 3.10+. Собирается на машине с интернетом:

```bash
bash offline/build_kit.sh    # -> dist/MonitoringSIP_offline_<hash>.zip
```

В архив идёт код из HEAD (незакоммиченное не попадает). Инструкция для установщиков —
`offline/ИНСТРУКЦИЯ.txt` (кладётся в корень архива). Версии зависимостей — `offline/requirements.lock`.

## Сборка в exe (опционально)

Для деплоя на Windows без Python есть спека PyInstaller:

```bash
pip install pyinstaller
pyinstaller server.spec
```

Готовый бинарь — в `dist/`. HTML-шаблоны (`login.html`, `panel.html`) и `static/` вшиты в сборку.
