# Три виртуальных телефона

Локальный интерактивный стенд для Monitoring SIP: три телефона **101**, **102** и **103**. Можно набирать номера, звонить друг другу, отвечать трубкой, громкой связью или гарнитурой, удерживать и переводить звонки, включать DND, mute и переадресацию, отключать регистрацию и питание.

На Windows запусти **`start_phone_lab.cmd`** из корня проекта. Используется проектная `.venv`, если она существует; иначе нужен Python с зависимостями из `requirements.txt`. Повторный запуск открывает уже работающий стенд.

На любой системе из корня проекта:

```sh
python -m simulator --open
```

Телефоны: **http://127.0.0.1:18080/lab**. Настоящая панель мониторинга доступна на той же странице и отдельно по ссылке **http://127.0.0.1:18080/lab/monitor**. В отдельном процессе стенда вход выполняется автоматически под его тестовым пользователем.

## Первый звонок

1. На телефоне 101 набери **102** и нажми зелёную кнопку вызова.
2. На 102 сними трубку или нажми кнопку ответа, громкой связи либо гарнитуры.
3. Удерживай разговор, переключай режимы и смотри изменения карточек в настоящем мониторинге.
4. Через несколько секунд положи трубку. В истории появятся входящий и исходящий звонки. Записи с длительностью вызова меньше трёх секунд мониторинг не сохраняет; его длительность включает ожидание ответа. Таймер на виртуальном телефоне считает время после ответа.

Кнопка сброса возвращает телефоны в исходное состояние; накопленная история остаётся. Для отдельного чистого эксперимента укажи новый пустой каталог:

```sh
python -m simulator --port 18081 --data-dir ./my-phone-lab --open
```

По умолчанию данные хранятся в `%LOCALAPPDATA%\MonitoringSIP\phone-lab` на Windows или `~/.local/share/MonitoringSIP/phone-lab` на Linux. Программа откажется использовать непустой чужой каталог. Рабочие `auth.json`, `.env`, карточки и история основной программы не используются. Для остановки закрой процесс стенда (Ctrl+C в его консоли).

## Что проверяет стенд

Каждый виртуальный телефон отправляет HTTP GET в настоящий `/event`. Обычные обработчики Monitoring SIP обновляют карточки, SQLite-историю, журнал и Socket.IO-панель. URL включают номер собеседника, IP, MAC, модель и идентификатор звонка. Для самих событий нет замены обработчиков или прямой записи состояний в мониторинг.

Виртуальные IP `192.0.2.101`–`192.0.2.103` не создаются в сети: в процессе стенда их ping зависит от питания телефона. Работает обычный debounce мониторинга: после двух неудач меняется ping, после трёх появляется OFFLINE (до 30 секунд). При включении телефон сразу отправляет событие регистрации, которое возвращает карточку в рабочее состояние; восстановление только по ping требует двух успешных проб. Снятая регистрация и выключенное питание — разные действия.

Это модель телефонных событий без передачи голоса и без исполнения прошивки Yealink. Совместимость реального CFG, подстановка макросов и порядок событий конкретной прошивки требуют проверки на аппарате или по его записанной трассе.

События `Handfree` и `Headset` моделируются как нажатия клавиш согласно [описанию Yealink](https://support.yealink.com/docs/sip-t53/remote-control/93527fc627104ded93cf7f11a1c2dbe2); снятие физической трубки отдельно посылает `Off Hook`. Обнаруженный нюанс Rel 1.1.1: мониторинг может сохранять значок громкой/гарнитуры после изменения аудиорежима до завершения звонка. Сам разговор при этом продолжается. Стенд показывает это поведение обычного обработчика, без подмены его флагов.
