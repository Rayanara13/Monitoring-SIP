ИНЕЙ 1.3.2 — установка без интернета (Windows и Linux)
======================================================

Панель мониторинга трубок Yealink: кто в разговоре, кто звонит, кто офлайн,
история звонков. Работает в браузере, сервер — этот ноутбук.

Интернет НЕ нужен. Python и все библиотеки уже лежат в архиве, ставить
ничего не надо: распаковал -> запустил.

MonitoringSIP_1.3.2_offline_windows_x64_<hash>.zip — Windows x64.
MonitoringSIP_1.3.2_offline_linux_x64_<hash>.zip — Linux x86_64.
MonitoringSIP_1.3.2_offline_linux_arm64_<hash>.zip — Linux ARM64 (aarch64).

WINDOWS X64 ЧЕРЕЗ CODE → DOWNLOAD ZIP
------------------------------------
  1) На главной странице Monitoring-SIP на GitHub нажми Code → Download ZIP.
     Перенеси скачанный архив на флешке и распакуй его целиком на локальный диск.

  2) При обновлении Rel 1.0 перенеси данные перед запуском по разделу 6.

  3) Запусти start_windows.bat в корне распакованного архива. Лаунчер проверит
     вложенный Windows-комплект и распакует его в папку MonitoringSIP без сети.
     Рабочие данные хранятся в MonitoringSIP\app. Открой в браузере
     http://localhost:8000, если порт не менялся.

ПЕРЕНОС ГОТОВОГО КОМПЛЕКТА ИЗ RELEASES
--------------------------------------
  1) Подключи USB-накопитель к компьютеру с интернетом. Открой GitHub Releases
     проекта Иней (Monitoring-SIP) и скачай на USB готовый ZIP для платформы
     сервера и SHA256SUMS.txt из того же релиза. Выбери windows_x64,
     linux_x64 или linux_arm64 в имени архива. На Linux командой uname -m
     можно проверить архитектуру.

  2) Если администратор выдал файл подключения, перенеси его отдельно от ZIP.

  3) Подключи USB к серверу в закрытой сети. Скопируй ZIP и SHA256SUMS.txt
     на локальный диск сервера и сверь SHA-256. На Linux используй
     sha256sum "<имя ZIP>", на Windows — команду PowerShell
     Get-FileHash -Algorithm SHA256 -LiteralPath "<имя ZIP>".

  4) Распакуй ZIP на локальный диск. Внутри уже есть папка MonitoringSIP.
     Выполни команду для своей платформы из каталога, куда скопирован ZIP.
     Windows (PowerShell)
       Expand-Archive -LiteralPath "<имя ZIP>" -DestinationPath "$env:LOCALAPPDATA"
     Linux
       unzip "<имя ZIP>" -d "$HOME"
     Запусти приложение из распакованной папки MonitoringSIP по инструкции
     для своей платформы. USB после копирования можно извлечь.

1. ЧТО В АРХИВЕ
---------------
  start_windows.bat          запуск в комплекте Windows (двойной клик)
  open_port_windows.bat      открыть порт 8000 в брандмауэре Windows (от администратора)
  start_linux.sh             запуск в комплекте Linux
  install_service_linux.sh   автозапуск на Linux через systemd (по желанию)
  ИНСТРУКЦИЯ.txt             этот файл
  VERSION.txt                версия сборки
  run.py                     общий лаунчер (руками запускать не нужно)
  app\                       сама программа; здесь же появятся её данные
  vendor\                    библиотеки (Flask, Socket.IO и др.)
  runtime\                   встроенный Python 3.13 для платформы архива

Требования:
  * Windows 10 или 11 x64 либо Linux x86_64 или aarch64 с glibc.
    На Linux архитектуру можно проверить командой uname -m.
  * Свободный порт 8000 по умолчанию. Если он изменён через
    MONITORING_SIP_PORT, используй выбранный порт в адресах и брандмауэре.
  * Ноутбук и телефоны/базы Yealink в одной сети (или между ними есть маршрут).

Если на машине уже стоит свой Python 3.10 или новее — ничего страшного, он не
мешает. Запуск сперва берёт встроенный Python, а свой использует только как
запасной (если встроенный почему-то не запустился).


2. УСТАНОВКА НА WINDOWS
-----------------------
  1) Распакуй архив целиком в простую папку, например  C:\MonitoringSIP
     (не в "Program Files" — программе нужно писать свои файлы рядом с собой).
     Если архив пришёл из интернета/почты: до распаковки ПКМ по zip -> Свойства ->
     поставить галку "Разблокировать" -> OK. Иначе Windows будет ругаться на .bat.

  2) ПКМ по open_port_windows.bat -> "Запуск от имени администратора".
     Должно написать "OK: port 8000 is open". Без этого телефоны не достучатся до
     сервера. (Альтернатива: при первом запуске Windows сама спросит про доступ
     для python.exe — нажать "Разрешить", отметив "Частные сети".)

  3) Двойной клик по start_windows.bat. Откроется чёрное окно — это и есть сервер.
     Пока окно открыто, панель работает. Закрыл окно = сервер остановлен.

  4) ПЕРВЫЙ ЗАПУСК: в окне будет напечатано один раз:
         Логин: admin
         Пароль: ....
         Токен для /event: ....
     ОБЯЗАТЕЛЬНО СОХРАНИ пароль и токен (сфотографируй/перепиши). Больше они
     нигде не показываются, в файлах хранится только хэш пароля.

  Автозапуск при входе в Windows (по желанию):
     Win+R -> shell:startup -> Enter. В открывшуюся папку положи ЯРЛЫК на
     start_windows.bat (ПКМ по файлу -> Отправить -> Рабочий стол (создать ярлык),
     потом перенести ярлык в эту папку).


3. УСТАНОВКА НА LINUX
---------------------
  1) Распакуй архив, например в домашнюю папку:
         unzip "<имя ZIP>" -d "$HOME"
     Получится папка ~/MonitoringSIP. Если нет команды unzip — распакуй
     файловым менеджером или командой python3 -m zipfile -e "<имя ZIP>" "$HOME".

  2) Запуск:
         bash ~/MonitoringSIP/start_linux.sh
     (именно через "bash ..." — так работает, даже если потерялись права на файлы).
     Остановка — Ctrl+C.

  3) ПЕРВЫЙ ЗАПУСК: как и на Windows, в терминале один раз печатаются логин,
     пароль и токен admin — СОХРАНИ их.

  4) Брандмауэр (если включён):
         Ubuntu/Debian/Astra (ufw):   sudo ufw allow 8000/tcp
         РЕД ОС/Alt/Fedora (firewalld): sudo firewall-cmd --permanent --add-port=8000/tcp
                                        sudo firewall-cmd --reload

  5) Автозапуск как служба (по желанию, после шага 3!):
         sudo bash ~/MonitoringSIP/install_service_linux.sh
     Сервер будет подниматься сам при загрузке. Смотреть лог службы:
         journalctl -u monitoring-sip -f
     Удалить службу:
         sudo bash ~/MonitoringSIP/install_service_linux.sh --remove
     Пока работает служба, start_linux.sh вручную НЕ запускать (порт будет занят).


4. ПЕРВЫЙ ВХОД И НАСТРОЙКА ПАНЕЛИ
---------------------------------
  1) На самом ноутбуке открой браузер:  http://localhost:8000
     Войди как admin с паролем из первого запуска.

  2) Узнай IP ноутбука в сети телефонов:
         Windows:  Win+R -> cmd -> ipconfig          (строка "IPv4-адрес")
         Linux:    ip -brief addr
     Лучше закрепить за ноутбуком постоянный IP (статика или бронь на роутере),
     иначе после перезагрузки адрес сменится и телефоны перестанут слать события.
     С других компьютеров панель открывается по  http://<IP-ноутбука>:8000

  3) Добавь карточки телефонов: номер, имя, IP трубки/базы (по IP идёт ping —
     показ "офлайн"). События от номеров без карточки игнорируются.

  4) Новых пользователей создаёт admin в панели (раздел "Регистрация пользователя").
     У каждого пользователя свой токен для /event.

  5) Если администратор выдал файл подключения, открой страницу подключения
     в панели и загрузи выданный JSON.


5. НАСТРОЙКА ТЕЛЕФОНОВ YEALINK (Action URL)
------------------------------------------
В веб-интерфейсе трубки/базы: Функции -> Action URL (Features -> Action URL).
Там 48 полей. Готовые адреса под КАЖДОЕ поле есть в панели:

  вкладка "Тесты" -> "Настройка телефонов: Функции -> Action URL"

Строки идут в том же порядке, что поля на странице телефона, у каждой кнопка
"Копировать". Вставить в одноимённое поле, в конце нажать "Сохранить".
Адрес выглядит так (одна строка, без пробелов):

  http://<IP-ноутбука>:8000/event?token=<ТОКЕН>&state=<STATE>&local=$active_user&remote=$remote&ip=$ip&mac=$mac&call_id=$call_id

  <ТОКЕН> — токен того пользователя, в чьей панели должен светиться телефон.
  $active_user, $remote, $ip, $mac, $call_id телефон подставляет сам — менять не надо.

Если на телефоне отвечают кнопкой громкой связи, не снимая трубку, обязательно
заполнить поля "Гарнитура" и "Громкая связь" — по ним панель видит ответ.

Проверка пары "Занятость абонента" / "Занято": снять трубку — в разделе
"Последние события от телефонов" (там же, на вкладке "Тесты") должно прийти
"Занятость абонента". Если пришло "Занято" — адреса этих двух полей поменять
местами.

Старые настройки (state=Setup, Ringing, Connected, Idle, Hold, DND, OffHook,
OnHook) продолжают работать, перенастраивать старые телефоны не обязательно.

Проверка без телефона: открой в браузере на ноутбуке
  http://localhost:8000/event?token=<ТОКЕН>&state=Ringing&local=<номер-карточки>&remote=123
Карточка с этим номером должна загореться "входящим". Вернуть:
  тот же адрес, но  state=Idle


6. ГДЕ ДАННЫЕ, БЭКАП, ОБНОВЛЕНИЕ
-------------------------------
Всё, что создаёт программа, лежит в папке app:
  app\auth.json      пользователи (хэши паролей) и их токены
  app\.env           секретный ключ сессий (файл скрытый на Linux)
  app\users_data\    карточки, история звонков (call_history.db), лог app.log

Бэкап = скопировать эти три пункта (лучше при остановленном сервере).

Обновление с Rel 1.0
  1) Распакуй новый архив в отдельную папку. Если скачал через Code → Download ZIP,
     открой в ней PowerShell и выполни .\start_windows.bat --prepare.
     Команда подготовит MonitoringSIP\app без запуска сервера.
  2) Останови старый сервер. Из каталога его данных скопируй auth.json, .env
     и users_data в MonitoringSIP\app. Если рядом с auth.json есть phones.json,
     скопируй и его. Сохрани старую папку как резервную копию.
  3) Запусти новый сервер. Для архива с кнопки Code используй start_windows.bat
     из корня распакованного архива. Проверь вход, телефоны и историю по прежнему
     адресу. При сохранении IP и порта Action URL телефонов остаются рабочими.

  Открытые в браузере панели после обновления покажут внизу "Сервер обновлён" —
  нажать "Обновить". Панели старой версии 1.0 этого не умеют: один раз
  обновить страницу вручную (Ctrl+F5).


7. ТРИ ВИРТУАЛЬНЫХ ТЕЛЕФОНА
---------------------------
Из распакованной папки запусти команду для своей платформы.
  Windows (PowerShell)
    .\start_windows.bat --lab --open
  Linux
    bash start_linux.sh --lab --open

Телефоны открываются по адресу http://127.0.0.1:18080/lab. Позвони с 101 на 102,
ответь, поставь разговор на удержание и заверши вызов. Панель на той же
странице покажет состояние телефонов. Стенд доступен на этом компьютере и
хранит тестовые данные отдельно от рабочего приложения.


8. ПРОБЛЕМЫ
-----------
* Потерян пароль admin.
    Остановить сервер, удалить (лучше переименовать) app\auth.json, запустить —
    создастся новый admin с новым паролем и НОВЫМ токеном. Внимание: остальные
    пользователи тоже пропадут, а в телефонах придётся заменить токен.

* Окно сразу закрывается / "ERROR: no working Python 3.10+ found".
    Архив распакован не полностью (проверь, что есть runtime\windows\python.exe
    или runtime/linux/python/bin/python3.13) или распакован прямо "внутрь zip"
    без извлечения. Распакуй заново, целиком.
    Windows 7/8 встроенный Python не поддерживается — нужна Windows 10/11.
    На Linux x86_64 и aarch64 нужны разные архивы. Сверь имя архива с
    результатом uname -m. Нативные библиотеки комплекта рассчитаны на
    CPython 3.10–3.15 той же архитектуры.

* "Address already in use" / "WinError 10048" / порт занят.
    Сервер уже запущен (второе окно, служба на Linux) или порт 8000 занят другой
    программой. Закрой лишнюю копию.

* Панель на ноутбуке открывается, а с других ПК / телефоны не шлют события.
    - брандмауэр (раздел 2 шаг 2 или раздел 3 шаг 4);
    - в Action URL правильный IP ноутбука и порт 8000;
    - правильный токен (именно того пользователя, в чьей панели карточка);
    - карточка с таким номером добавлена;
    - проверка из браузера (раздел 5) работает — значит дело в сети/телефоне.

* Все телефоны "офлайн", хотя работают (Linux).
    ping должен быть доступен обычному пользователю. Проверь:  ping -c1 <IP трубки>
    Если "Operation not permitted":
        sudo sysctl -w net.ipv4.ping_group_range="0 2147483647"
    Если команды ping нет — пакет iputils-ping (есть на установочном диске дистрибутива).

* Для разбора ошибки сообщи версию, время и действие, на котором она появилась.
